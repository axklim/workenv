# workenv v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `we` around the design in the spec: environments keyed by an
integer id, GitHub refs stored as full URLs, tmux sessions named
`<project>-<branch>`, worktrees placed by a configurable path template on
normal (non-bare) clones, `open`/`attach` as one path, and a folded `ls`.

**Architecture:** Six focused packages feed one orchestrator. A new
`internal/wtpath` renders the worktree-path template; `internal/config`
carries it plus `projects_path`; `internal/state` is the id-keyed registry;
`internal/naming`, `internal/gh`, `internal/gitx`, `internal/target` supply
names, GitHub metadata, git operations and target parsing; `internal/we`
resolves a target to an environment and repairs it; `cmd/we` is the CLI and
all rendering.

**Tech Stack:** Go 1.23 standard library only (`text/template` for the path
template); `git`, `gh`, `tmux`, Ghostty driven through `execx.Runner`; tests
use `execx.Fake`; the toolchain runs in Docker via the Makefile.

**Spec:** `docs/superpowers/specs/2026-08-17-workenv-design.md` — the binding
authority. Every task references its sections; read the spec before writing
code, and prefer it over this plan's prose if they ever disagree.

## Global Constraints

- Standard library only — no new `go.mod` requirements. Go 1.23.5,
  gofmt-clean.
- Every git/gh/tmux/ssh call goes through `execx.Runner`; tests script them
  with `execx.Fake` (prefix match on `"name arg arg"`, unmatched → success
  with empty output).
- Run tests with the containerised toolchain from the repo root: `make check`
  (gofmt, vet, tests) or, for one package,
  `docker run --rm -v "$PWD":/src -w /src -v "$HOME/.cache/workenv-go":/cache -u $(id -u):$(id -g) -e HOME=/cache -e GOCACHE=/cache/build -e GOMODCACHE=/cache/mod -e CGO_ENABLED=0 -e GOFLAGS=-buildvcs=false golang:1.23.5 go test ./internal/<pkg>/`
- Names fixed by the spec. Config keys: `projects_path`, `worktree_path`,
  `claude_cmd`, `remote_we`. Record fields: `id`, `project`, `branch`,
  `tmux_session`, `worktree_path`, `repo_path`, `issues`, `prs`,
  `created_at`, plus top-level `next_id` and `envs`. Commands: `open`,
  `attach`, `list` (`ls`), `show`, `delete` (`rm`, `down`). Flags: `--repo`,
  `--branch`, `--session`, `--wt`, `--host`, `--no-terminal`, `--force`,
  `--delete-branch`, `--keep-worktree`, `-l`.
- Session name is `<project>-<branch>`, both sanitized. No `we-` prefix, no
  issue/PR number in any name.
- tmux user options on sessions `we` creates: `@workenv=1`, `@workenv_id=<id>`.
- GitHub refs are canonical URLs:
  `https://github.com/<owner>/<repo>/(issues|pull)/<n>`, no trailing slash.
- Markdown in the repo: prose wrapped at ~90 columns, tables narrow with
  aligned pipes.
- Commit after each task, conventional prefix, body wrapped at 72, trailer
  `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- This is a rewrite of an unreleased format: no migration code, no
  backwards-compatible aliases. Delete what the spec replaced.

### Task 3: `internal/state` — the id-keyed registry

**Files:**
- Rewrite: `internal/state/state.go`, `internal/state/state_test.go`

**Spec:** *State*.

**Interfaces:**
- Consumes: nothing from other tasks.
- Produces:
  ```go
  type Env struct {
      ID           int       `json:"id"`
      Project      string    `json:"project"`
      Branch       string    `json:"branch"`
      TmuxSession  string    `json:"tmux_session"`
      WorktreePath string    `json:"worktree_path"`
      RepoPath     string    `json:"repo_path"`
      Issues       []string  `json:"issues,omitempty"`
      PRs          []string  `json:"prs,omitempty"`
      CreatedAt    time.Time `json:"created_at"`
  }

  type Store struct {
      Path   string  // file location, not serialised
      NextID int     // next_id
      Envs   []*Env  // envs
  }

  func DefaultPath() string                      // $XDG_STATE_HOME/workenv/envs.json
  func Load(path string) (*Store, error)         // missing file → empty store
  func (s *Store) Save() error                   // atomic
  func (s *Store) ByID(id int) *Env
  func (s *Store) BySession(session string) *Env
  func (s *Store) ByBranch(repoPath, branch string) *Env
  func (s *Store) ByWorktree(path string) *Env
  func (s *Store) ByRef(url string) *Env         // issues or prs
  func (s *Store) Matching(pred func(*Env) bool) []*Env
  func (s *Store) Add(env *Env) *Env             // assigns ID, bumps NextID
  func (s *Store) Remove(id int) bool
  func (s *Store) Link(env *Env, issues, prs []string)
  ```

**Behaviour:**
- On-disk shape is `{"next_id": N, "envs": [...]}`; `Save` writes
  `envs: []` rather than `null`, and is atomic (temp file in the same
  directory + rename, 0600 is fine).
- `Add` assigns `env.ID = max(s.NextID, 1)` when `env.ID == 0`, then sets
  `NextID = env.ID + 1`. An explicit non-zero `ID` is respected and still
  advances `NextID` past it. Ids are never reused after `Remove`.
- `Load` on a file whose `next_id` is missing or below the highest existing
  id raises it to `max(id)+1`, so a hand-edited file cannot hand out a
  duplicate.
- `ByBranch` keys on `RepoPath` (not project) — two clones of one repository
  share a project name but are different repositories.
- `Link` appends each URL to `Issues`/`PRs` unless it is already there or
  belongs to a *different* environment. Comparison is exact string equality;
  canonicalisation is the caller's job.
- Lookups return `nil` when nothing matches.

### Task 5: `internal/we` — resolution, open/attach, delete, list

**Files:**
- Rewrite: `internal/we/we.go`, `internal/we/we_test.go` (keep
  `internal/we/helpers_test.go`)

**Spec:** *Model*, *Naming*, *Placement*, *Targets*, *Resolution*,
*Commands*, *Listing* (the data side).

**Interfaces:**
- Consumes: everything from Tasks 1–4, plus unchanged `execx`, `tmuxx`.
- Produces:
  ```go
  type Env struct {
      Cfg        config.Config
      R          execx.Runner
      GOOS       string
      Cwd        string
      InsideTmux bool
      StatePath  string
  }

  type OpenOptions struct {
      Target                target.Target
      Repo                  string // --repo <name|path>
      Branch, Session, Wt   string // creation overrides
      AttachOnly, NoTerminal bool
  }

  type OpenResult struct {
      ID                              int
      Project, Branch, Session        string
      WorktreePath, RepoPath          string
      Created                         bool
      IgnoredOverrides                []string // e.g. ["--branch", "--wt"]
  }

  type DeleteOptions struct{ Force, DeleteBranch, KeepWorktree bool }

  type Item struct {
      ID                              int
      Project, Branch, Session        string
      SessionState                    string // attached | detached | none
      WorktreePath, RepoPath          string
      Issues, PRs                     []string
      Exists, Current                 bool
      CreatedAt                       time.Time
  }

  func (e *Env) Open(opts OpenOptions) (OpenResult, error)
  func (e *Env) Delete(t target.Target, repo string, opts DeleteOptions) error
  func (e *Env) List() ([]Item, error)
  func (e *Env) Show(t target.Target, repo string) (Item, error)
  func (e *Env) AttachRemote(host, session string) error
  ```

**Behaviour:** follow the spec's *Resolution* section literally. Notes where
implementation detail matters:

- **Repository resolution** (`--repo`, cwd, projects path, clone): a `--repo`
  value containing a path separator or starting with `~` is a path (expanded,
  must be a repository); a bare name is `gitx.FindProjectDir(cfg.ProjectsPath,
  name)`. Otherwise `gitx.RepoRoot(cwd)`. For issue/PR/repo targets, prefer
  the cwd's repository when its origin matches the target, then
  `<projects_path>/<repo>`, then clone (only when not `AttachOnly`).
- **Creation** assigns, in order: branch (per target kind), project
  (`gitx.ProjectName`), session (`opts.Session`, else
  `naming.SessionName(project, branch)`), worktree path (`opts.Wt`, else an
  adopted worktree on that branch, else `wtpath.Render(cfg.WorktreePath, …)`).
  A `--wt` value with a separator or leading `~` is used verbatim; a bare name
  replaces the leaf of the rendered path.
- **Guards before creating:** `st.BySession(session)` and
  `st.ByWorktree(path)` must be nil, else an error naming the conflicting id
  and suggesting `--session` / `--wt`.
- **Branch preparation:** fork PR → `gitx.FetchPRBranch`; same-repo PR →
  `gitx.EnsureOriginBranch`.
- **Repair on every open and attach:** worktree directory missing → `Prune`
  then `AddWorktree`; tmux session missing → `New` + tag + `RunInFirstWindow`;
  branch refreshed from `gitx.CurrentBranch`.
- **Adoption of a live session:** if `tmux.Has(session)` but the session is
  not `@workenv`-tagged, return an error suggesting `--session`. A tagged
  session is reused.
- **Overrides on a hit:** never applied; the names of the ones that were
  passed go into `OpenResult.IgnoredOverrides` for the CLI to report.
- **Delete:** registry-only resolution; an explicit `--repo` disables the
  global unique-branch fallback; kill session, remove worktree (`Force`;
  missing directory → `Prune` only), optional `DeleteBranch`, `Remove(id)`,
  `Save`. A target not in the registry that names a live `@workenv`-tagged
  session kills that session.
- **List:** one `Item` per record, sorted by id; `SessionState` from
  `tmuxx.List()`; `Exists` from `os.Stat(WorktreePath)`; `Branch` refreshed
  live when the directory exists; `Current` when `e.Cwd` is inside
  `WorktreePath`. `List` does not write.
- **Show** resolves like `Delete` (registry only) and returns the same
  `Item`.

**tmuxx changes** (same task, small): `New(session, dir string, id int)` sets
`@workenv=1` and `@workenv_id=<id>`; `List()` returns `Session{Name, ID,
Path, Attached}` parsed from
`#{session_name}\t#{@workenv_id}\t#{session_path}\t#{session_attached}`,
skipping rows with an empty id; add `IsWorkenv(name string) bool` using
`tmux show-options -t <name> @workenv`.
